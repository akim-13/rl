In this lesson, we will introduce a second class of solution methods for sequential decision problems: **Monte Carlo** methods. Unlike dynamic programming methods, which rely on having access to a perfect model of the environment's dynamics, Monte Carlo methods learn using only an agent's experience. This is significant, because it means that our agent can learn in an environment that it starts off knowing absolutely nothing about.

# Monte Carlo Policy Evaluation

Completion requirements

#### **Monte Carlo  
**

**Monte Carlo** methods are a class of solution methods that enable us to solve sequential decision problems without prior knowledge of our agent's environment. Instead of relying on a known world model, as dynamic programming methods do, Monte Carlo methods rely on experience generated by our agent in its environment.

Just like we did for dynamic programming methods last week, we're going to start off by looking at how Monte Carlo methods address the **policy evaluation** or **prediction** problem. Remember, this means computing the state-value function for a given policy.

We'll begin with a general outline of how Monte Carlo methods work, before adding successively more detail until we arrive at a concrete Monte Carlo policy evaluation algorithm.

Let's imagine that we have an agent following some arbitrary policy 𝜋 in an environment whose transition dynamics are fully unknown to us. We want to find the value function 𝑣𝜋 for our agent's policy in this environment.

Recall that the value function 𝑣𝜋 tells us the expected return that the agent would obtain if it started in a state 𝑠 and selected actions according to 𝜋 thereafter. To estimate the value of a state 𝑠 under a policy 𝜋, an MC method would first generate many episodes of experience, with our agent selecting actions according to 𝜋. We then look through all of the episodes, average all of the returns observed after our agent visits state 𝑠, and use this average as an estimate of that state's value.

This makes sense, because we are literally averaging returns generated after our agent visited state 𝑠 and followed 𝜋 thereafter. This idea of collecting and averaging **sample returns** lies at the heart of all MC methods.

**Based on this, a very high-level MC algorithm for performing policy evaluation would work to:**

1. Simulate many episodes of interaction with an environment.
2. Average the sample returns earned after visiting each state.

How would this look in a little more detail? Following the high-level algorithm discussed above, we'd start our agent in state some initial state and let it select actions according to 𝜋 until it reaches a terminal state. This would give us a single sample trajectory:

𝑆0,𝐴0,𝑅1,𝑆1,𝐴1,𝑅2,…,𝑆𝑇−1,𝐴𝑇−1,𝑅𝑇

For each state that our agent visited along this trajectory, we'd compute the discounted sum of rewards observed after our agent's visit to that state. This discounted sum of rewards is known as a sample return, and it would form our estimate of the value of that state under policy 𝜋.

We can repeat this process many times. Each time, our agent would generate another episode of experience, from which we could compute new sample returns for each state. Our new estimates for the values of each state would be the average of all of the sample returns we'd computed for that state so far.

Unless both our agent's policy and environment are deterministic, it is likely that each episode of experience that our agent generates will be different. These differences might be caused by many things. For instance,

- our agent might start each episode in a different initial state,
- stochasticity in the environment might cause taking the same action in the same state to lead to different outcomes in different episodes, or
- stochasticity in our agent's policy itself might cause it to choose different actions in the same state in different episodes.

Differences between episodes will likely mean differences between the sample returns computed for each state. However, after sufficient repeated sampling, the average of all the sample returns generated by our agent should converge upon the true expected value of each state.

An expanded example, with some sample results, can be found in the course textbook as part of this week's required reading. It discusses using Monte Carlo methods to perform policy evaluation in the card game of blackjack.

When performing an update, the DP method looks ahead one step at all the actions that might be chosen according to policy 𝜋, as well as all the possible rewards and next states reachable via those actions. The update is then based on those possible rewards and bootstraps off our existing estimates of the values of those possible next-states.

In contrast, the backup diagram for a Monte Carlo method would look like this:

**A backup diagram representing a Monte Carlo backup for estimating 𝑣𝜋.** [[1]](https://moodle.bath.ac.uk/mod/page/view.php?id=1499975&forceview=1#footnote-2)

This is clearly very different to the dynamic programming backup diagram. The first obvious difference is that, instead of taking into account all the possible actions (and resulting rewards and next-states) available in a given state, Monte Carlo methods sample only a single action in a given state. The second clear difference is that, instead of looking forward only one time step and then bootstrapping off the values of a state's immediate successors, Monte Carlo methods continue sampling actions until a terminal state is reached, and base their value estimates on the rewards earned along the way. We can say that Monte Carlo methods **sample** but, unlike dynamic programming methods, that they **don't bootstrap**.

Monte Carlo methods generate full episodes of experience following a policy 𝜋, compute sample returns using the rewards observed in those trajectories, and base their updates solely on those sample returns.

# First-Visit and Every-Visit Methods

Completion requirements

As our agent generates an episode of experiences by following its policy 𝜋, it may visit many states before it eventually reaches a terminal state. In many environments, including the gridworld environments we've seen previously, it might well be possible for our agent to visit a single state multiple times in a single episode. If this happens, we're left in a situation where we have multiple points in the trajectory from where we could start computing our sample return for that state.

There are two well-studied solutions to this issue. The first is to only compute the return following the **first** visit to a state during an episode (i.e., the visit closest to the start of the episode). The second is to compute the returns following **every** visit to a state during an episode.

Monte Carlo methods that compute returns in these two ways are known as **first-visit** and **every-visit** methods, respectively.

This week, we will focus on first-visit Monte Carlo algorithms. However, they can all be easily modified into every-visit versions, and all the central ideas we discuss apply to both cases. Importantly, both first-visit and every-visit methods are guaranteed to converge (either to the true value function or to an optimal policy) under the same conditions.

Illustrated below is a trajectory generated in an arbitrary environment by an agent following some arbitrary policy. The agent visits five distinct, numbered states and earns a series of rewards. Notice that, along the trajectory, the agent visits state 2 twice.

**An example trajectory generated by an agent.**

Let's compute the sample return for state 2 using both a first-visit approach, and then an every-visit approach. Throughout this example, we'll assume that the problem is undiscounted (i.e., 𝛾=1).

We'll start with the first-visit case. The first visit to state 2 occurs directly after the agent leaves the starting state 1. The discounted sum of rewards following this visit to state 2 is:

−1.0+−1.0+−1.0+10.0=7.0

As we only count the first visit to each state, our single sample return for state 2 is 7.0, and this forms our estimate for the value of state 2.

Now, we'll look at the every visit case. Again, we look at that first visit to state 2, but also the second visit to the state which occurs towards the end of the episode. So, we end up having to compute two sample returns for state 2:

−1.0+−1.0+−1.0+10.0=7.0

+10.0=10.0

The two sample returns for state 2 that we end up with are 7.0 and 10.0. Averaging these two sample returns, we get an estimate for the value of state 2 of 8.5.

# Estimating Action-Values

Completion requirements

When we were trying to find an optimal policy using dynamic programming methods, we determined the "best" action available in a given state 𝑠 by looking at the available actions and choosing the one which led to the highest expected immediate rewards and next-state values.

We were able to perform this one-step look-ahead because dynamic programming methods assume access to a perfect model of the agent's environment. Because we were able to look ahead one step to see the possible successors of each state, we could perform policy improvement while only relying on the state-value function 𝑣𝜋.

We are now working with Monte Carlo methods, which do not assume prior knowledge of the environment's transition dynamics. This means that we cannot perform this one-step look-ahead anymore, and that state-values will be insufficient for learning optimal policies.

Because of this, it makes more sense to estimate the action-value function 𝑞𝜋 instead of the state-value function 𝑣𝜋. Recall that the action-value 𝑞𝜋 tells us the expected return of taking action 𝑎 in state 𝑠 and then following policy 𝜋 thereafter. If we build up estimates of all of the actions available in a given state, then we can choose the highest-valued action without having to do a one-step look-ahead.

Luckily for us, estimating action-values is very similar to estimating state-values, as we have done previously. The main difference is that we previously computed sample returns observed after visiting a state 𝑠, whereas we now compute sample returns observed after visiting a state 𝑠 and taking action 𝑎. For convenience, we refer to this as a visit to the state-action pair (𝑠,𝑎).

# Exploration via Exploring Starts and Soft Policies

Completion requirements

Monte Carlo methods for estimating the action-value function 𝑞𝜋 for a policy 𝜋 are only guaranteed to converge if we make sure that every possible state-action pair can be visited. That is, if we generated an infinite number of episodes, we'd expect the number of visits to each state-action pair to approach infinity.

This is important because Monte Carlo methods require sample returns following a state-action pair in order to estimate its value. This becomes even more important when solving the control problem, where we might want to improve the action choices made by our current policy. If certain actions in some states are never chosen, we will have no way to evaluate whether selecting them is better or worse than our current policy.

This is known as the problem of **maintaining exploration**. We're now going to discuss two different solutions to this problem.

#### **Exploring starts**

The first way to ensure that every state-action pair is visited is by giving each episode a non-zero probability of starting in any state-action pair. That is, we say that the initial state of an episode can be any state 𝑠∈𝑆, and that the first executed action can be any 𝑎∈𝐴(𝑠), regardless of the action that 𝜋 would have chosen.

We call this the assumption of **exploring starts**.

This assumption solves the problem of ensuring that every state-action pair will be visited infinitely many times across an infinite number of episodes. It can be useful in cases where we are simulating a simple environment or know the bounds of the state and action sets ahead of time.

Of course, though, it might not always be practical or possible to allow our agent to start in any state-action pair.

An alternative to exploring starts is to ensure that our agent's policy assigns non-zero probabilities to every action available in every state.

𝜋(𝑎|𝑠)>0∀𝑠∈𝑆,∀𝑎∈𝐴(𝑠)

That is, we ensure that there is some chance (however small) that our agent will take every action available in every state. We refer to such policies as **soft policies**. Given an infinite number of episodes, this will ensure that every state-action pair is visited an infinite number of times.

One of the most common types of soft policy that we will encounter in RL is known as 𝜖-greedy policies. 𝜖-greedy policies are a type of soft policy which, for a given state, select the highest-valued action with probability 1−𝜖, and choose an action randomly with probability 𝜖. Formally, an 𝜖-greedy policy selects the highest-valued action with probability:

1−𝜖+𝜖|𝐴(𝑠)|

and selects each of the lower-valued actions with probability:

𝜖|𝐴(𝑠)|

Intuitively, 𝜖-greedy policies choose the "best" action most of the time, but occasionally explore randomly.

𝜖-greedy policies are themselves a subset of another class of soft policies, known as **𝜖-soft policies**. A policy is an 𝜖-soft policy as long as it satisfies the following constraint:

𝜋(𝑠,𝑎)≥𝜖|𝐴(𝑠)|∀𝑠∈𝑆,∀𝑎∈𝐴(𝑠)for some 𝜖>0

By definition, 𝜖-greedy policies satisfy this constraint, so it is easy to see that 𝜖-greedy policies are themselves instances of 𝜖-soft policies.

To end this section on maintaining exploration, we will quickly discuss how our agent's initial action-value estimates can impact its exploration early during training.

Consider a gridworld environment, similar to those discussed previously, where our agent must navigate from some starting state to some goal state and where the rewards are −1 for each action taken. In such an environment, the true value of all state-action pairs under the optimal policy will be negative with their magnitude depending on their distance from the goal.

If we set our initial action-value estimates for all state-action pairs to be 0, these initial estimates will be higher than whatever the true values are. These **optimistic initial values** help encourage our agent to explore early during training. This is because, as our agent takes actions and observes their resulting rewards and next-states, their values will be lowered below 0. This means that if there are any actions available in a given state that our agent has never tried before, their value will always be higher than those that it has tried before. Following a greedy or 𝜖-greedy policy, our agent will select these higher-valued actions that it has not selected before instead of the lower-valued actions it has.

Optimistic initial value estimates are a simple way of ensuring that our agents prioritise selecting actions that have not been chosen before early during training, helping ensure sufficient exploration of the state-space.

# On-Policy vs Off-Policy Methods

Completion requirements

In RL, our agents often find themselves having to make a trade-off between **exploration** and **exploitation**. On one hand, they will want to exploit what they already know to maximise their long-term reward. On the other hand, they need to explore to find an optimal policy, because the policy they are currently following might be suboptimal.

Obviously, a policy that explores randomly isn't optimal, but exploration is necessary to find one. This leaves our agents in the difficult situation where they need to learn about a policy (i.e., the optimal policy) that is different to the policy that they're actually following (i.e., a policy that explores). What we really want is for our agents to be able to learn about the true optimal policy while following a suboptimal policy that explores.

The control methods we have examined so far are known as **on-policy methods**, where our **agents learn about the policy they are actually following**. If our agent is following a policy that explores, it will only ever be able to learn about policies that explore: it will never be able to learn about the optimal policy, only a near-optimal policy that explores.

We are now going to introduce **off-policy** methods, where our agent behaves according to a **behaviour policy** 𝑏, but actually learns about a different **target policy** 𝜋. For instance, 𝑏 might be a policy that explores, while 𝜋 is the optimal policy that doesn't explore.

A nice example problem that clearly demonstrates why off-policy methods are useful is the **cliff walking** problem. This environment is a gridworld, the layout of which is shown below.

This is an undiscounted, episodic task where our agent starts in the starting grid square marked 'S' and must navigate to the goal grid square marked 'G', where the episode terminates. Our agent can move deterministically 'North', 'South', 'East', or 'West'. Moving into a wall causes our agent to remain in the same grid square, and moving into 'The Cliff' returns our agent to the starting grid square. Our agent earns a reward of −1 per action, and an additional −100 for falling off the cliff. Let's suppose that our agent is following an 𝜖-greedy policy.

Let's first consider the case where our agent is learning using an on-policy method. Because on-policy methods can only learn about the policy that our agent is following, it will converge to a near-optimal policy that explores, instead of the true optimal policy, and would likely learn to take the 'safer path' marked on the diagram. Although this 'safer path' is not the shortest path to the goal, it takes into account the random exploration inherent in our agent's 𝜖-greedy policy, and helps prevent it from causing our agent to fall off the cliff.

If, on the other hand, our agent was learning using an off-policy method, it could learn about the optimal policy while following an 𝜖-greedy policy. That is, we would set the target policy 𝜋 to be the deterministic optimal policy, while setting the behaviour policy 𝑏 to be an 𝜖-greedy policy which explores. Because of this, our agent could learn the true shortest path, marked 'optimal path' on the diagram. Our agent would fall off the cliff more during training, due to random exploration, but the optimal policy that it learns at the end will not take failures due to this negative reward into account, precisely because the optimal policy would never actually choose these suboptimal actions.

We will be revisiting this example in future lessons when we look at further examples of on-policy and off-policy methods.

# Off-Policy Monte Carlo Control

Completion requirements

Now that we have introduced the concept of off-policy RL methods, which allow our agents to learn about a target policy 𝜋 (e.g., the optimal policy) while actually following a different behaviour policy 𝑏 (e.g., an 𝜖-greedy policy which explores), we are going to finish this lesson by looking at a concrete off-policy MC control algorithm.

Unfortunately, by their very nature, off-policy methods are more complex than their on-policy counterparts. So, before we can dive into a concrete algorithm, there are a couple of additional concepts that we need to introduce first.

In short, the goal of an off-policy method is to learn about a policy 𝜋 using experience generated by a different policy 𝑏. In order for this to be possible, we require that every action that would be selected by 𝜋 also has a chance of being selected by 𝑏. If this weren't the case, then our agent would never be able to learn about some of the actions that 𝜋 would choose. This is known as the assumption of \textbf{coverage}. Formally:

𝜋(𝑎|𝑠)>0⟹𝑏(𝑎|𝑠)>0

An easy way to ensure this is by making sure that 𝑏 is some kind of soft policy, at least in states where it is not identical to 𝜋.

Let's imagine that our agent has generated a number of episodes of experience following its behaviour policy 𝜋, and we have computed sample returns for each. Normally, if this were an on-policy method, we would form our action-value estimates by simply averaging the sample returns following each state-action pair. However, it's not so simple this time, because the value function we're estimating isn't the action-value function for the policy that generated the returns 𝑣𝑏, but the action-value function for a different policy 𝑣𝜋.

Instead of simply taking a weighted average of sample returns, we need to take a weighted average. The weight assigned to each sample return will be the relative probability of that sample return being generated following our target policy and behaviour policies, which we refer to as the \textbf{importance-sampling ratio} 𝜌. For a given trajectory 𝜏 generated by behaviour policy 𝑏 after starting in state 𝑆𝑡:

𝜏=𝐴𝑡,𝑆𝑡+1,𝐴𝑡+1,…,𝐴𝑇−1,𝑆𝑇

The probability of observing this trajectory 𝜏 under a policy 𝜋 would be:

𝑝(𝜏|𝑆𝑡,𝐴𝑡:𝑇−1∼𝜋)=𝜋(𝐴𝑡|𝑆𝑡)𝑝(𝑆𝑡+1|𝑆𝑡,𝐴𝑡)…𝜋(𝐴𝑇−1|𝑆𝑇−1)𝑝(𝑆𝑇|𝑆𝑇−1,𝐴𝑇−1)=∏𝑘=𝑡𝑇−1𝜋(𝐴𝑘|𝑆𝑘)𝑝(𝑆𝑘+1|𝑆𝑘,𝐴𝑘)

Unfortunately, this equation relies on the environment's transition dynamics 𝑝(𝑠′|𝑠,𝑎), which we do not assume access to when working with Monte Carlo methods. However, when we look at the relative probability of a trajectory 𝜏 occurring under our agent's target policy 𝜋 and its behaviour policy 𝑏, we get the following:

𝜌𝑡:𝑇−1=∏𝑇−1𝑘=𝑡𝜋(𝐴𝑘|𝑆𝑘)𝑝(𝑆𝑘+1|𝑆𝑘,𝐴𝑘)∏𝑇−1𝑘=𝑡𝑏(𝐴𝑘|𝑆𝑘)𝑝(𝑆𝑘+1|𝑆𝑘,𝐴𝑘)=∏𝑘=𝑡𝑇−1𝜋(𝐴𝑘|𝑆𝑘)𝑏(𝐴𝑘|𝑆𝑘)

Although the trajectory probabilities themselves relied on access to the environment's transition dynamics, 𝑝(𝑠′|𝑠,𝑎), these terms cancel out in the equation for the importance-sampling 𝜌. What we're left with is an equation that relies only on our target and behaviour policies.

In summary, when we're averaging the sample returns generated by our behaviour policy 𝑏 to estimate the action-value function for our target policy 𝜋, we weight each sample by its importance-sampling ratio 𝜌. This method, where we're just taking a normal weighted average, is known as \textbf{ordinary importance sampling}.

Beyond this week's required reading, the course textbook goes into further detail on the subject of importance sampling and introduces a second type known as weighted importance sampling. This is beyond the scope of this course, but curious students might find this additional content interesting.

This algorithm is simpler than the off-policy MC algorithm shown in the course textbook, and no guarantees are made regarding its performance or convergence properties, but it captures all of the off-policy concepts that we have introduced so far. **Pseudocode for a simple off-policy first-visit Monte Carlo control algorithm.**

At first glance, this algorithm is very similar to the on-policy MC control algorithms that we looked at earlier. Because of this, we will focus on the new features this algorithm introduces in our deep dive and skip over portions of pseudocode that are very similar to other algorithms we have already examined.

**Part 1: Behaviour policy**

The first major difference we observe when comparing this off-policy algorithm to the on-policy algorithms we have previously examined is in how episodes of experience are generated. Remember that, with off-policy methods, our agent generates experience by following a behaviour policy 𝑏 in order to learn about a target policy 𝜋. The behaviour policy 𝑏 needn't be fixed, and could be changed after, or even during, each episode, as long as it always has coverage of the target policy 𝜋.

An interesting thing to note is that, if we set 𝑏 and 𝜋 to the same soft policy, this algorithm becomes equivalent to the on-policy first-visit MC control algorithm for soft policies that we looked at earlier!

**Part 2: Ordinary importance sampling**

The next important difference to note is that instead of simply averaging the sample returns observed following each state-action pair, we now perform a weighted average using ordinary importance sampling. As we discussed, we weight each observed sample return by its importance-sampling ratio, 𝜌, which tells us the relative probability of observing a given trajectory occurring under our agent's target and behaviour policies.

Aside from this change, the remainder of the policy evaluation and policy Improvement steps remain largely the same as we've seen previously. An estimate of the action-value function 𝑞𝜋 is computed using the weighted average of sample returns for each state-action pair, and a deterministic policy 𝜋is derived by choosing actions greedily with respect to this estimate.

Notice how we are able to learn the optimal target policy while choosing actions according to a sub-optimal policy which explores!

**Part 3: Early termination**

The final difference is that we should terminate the algorithm's inner loop early if the behaviour policy 𝑏 selects an action different to what the target policy 𝜋 would select at a given time-step 𝑡. Essentially, this algorithm only learns from the 'tails' of episodes, from the end back until 𝑏 selects a different action to 𝜋.

The reason for this is the fact that 𝜋 is a deterministic policy: it chooses the highest-valued action with probability 1.0, and all other actions with probability 0.0. If 𝑏 chooses an action that 𝜋 would not choose, then it is not possible for that trajectory to have been taken by 𝜋. Therefore, we cannot learn anything from it.

We can also think of this in terms of the importance sampling ratio. If the action chosen at time-step 𝑡 by 𝑏 in a trajectory is different to the action that 𝜋 would have chosen, then the numerator of 𝜌 will become 0.0. This will be true for the trajectory starting at time-step 𝑡, and for the trajectories starting at all preceding time-steps. Therefore, we are free to terminate the processing of sample returns early for that episode.

In this week's lessons, we introduced our second class of solution methods for reinforcement learning problems: **Monte Carlo methods**.

Unlike dynamic programming methods, Monte Carlo methods do not require any prior knowledge of our agent's environment in order to learn. Instead, they form value estimates based on sample returns computed using full episodes of experience generated by our agent. Because of this, we were able to say that Monte Carlo methods do not bootstrap. We then looked at using Monte Carlo methods to solve the control problem by estimating action-values instead of state-values. We discussed the need to maintain exploration and then examined two on-policy Monte Carlo control algorithms that achieved this in different ways: one assumed exploring starts, and the other assumed the use of soft policies.

We finished this week's content by introducing the concept of off-policy methods, which learn about a target policy 𝜋 using experience generated by a behaviour policy 𝑏, and concluded by examining an off-policy version of the Monte-Carlo control algorithm we saw earlier in the week.

These methods represent a significant improvement over the dynamic programming methods we saw last week, which (1) assumed perfect access to a model of our agent's environment and (2) did not learn through experience. However, Monte Carlo methods still have a key limitation: they can only learn from full episodes of experience. If we are dealing with a problem that requires an agent to learn _within_ the first episode, or which is a continuing problem without any terminal states, then our Monte Carlo methods will struggle to learn.
